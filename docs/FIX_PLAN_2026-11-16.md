## 🔴 Волна 1 (P0 — High)

### [x] H1. Счёт «PDF: Готов», но скачать его нельзя

**Суть.** FK `invoices.pdf_file_asset_id → file_assets.id` объявлен с `ON DELETE SET NULL`
(миграция `0023_invoice.py:140`, модель `apps/api/app/models/invoice.py:70`). Удаление файла из
архива (`DELETE /api/v1/manager/files/{file_id}`, `apps/api/app/api/v1/manager/files.py:114-137`)
удаляет строку `file_assets` → FK обнуляет ссылку, а `invoices.pdf_status` остаётся `READY`.
Итог: UI показывает зелёный бейдж «PDF: Готов» и активную кнопку «Скачать счёт», сервер отдаёт
`409 INVOICE_PDF_NOT_READY`, а перерендерить нельзя (кнопка рендера показывается только при
`FAILED` — `apps/web/components/manager/OrderInvoicePanel.vue:325-327`).

**Воспроизведение (подтверждено на стенде 2026-11-16):**

1. `POST /api/v2/manager/orders/{id}/invoice` → счёт `СЧ-2026-000004`, `pdf_status=PENDING`.
2. Celery отрендерил PDF → `pdf_status=READY`, `pdf_file_asset_id=2dc2a01d…`.
3. `GET /api/v2/orders/invoices/{id}/download` → **200**, `application/pdf`, 13 455 байт.
4. `DELETE /api/v1/manager/files/{file_asset_id}` → **204**.
5. `GET /api/v2/orders/invoices/{id}/download` → **409** `invoice-pdf-not-ready`,
   при этом в БД `pdf_status=READY`, `pdf_file_asset_id=NULL`.

Тот же механизм задевает КП (`quotes.pdf_file_asset_id` — тоже `ON DELETE SET NULL`,
`apps/api/app/models/quote.py:99`).

**Шаги:**

- [x] **Шаг 1 — канон.** В `ARCHITECTURE_PLAN.md` §16 п.40 (счета на оплату) и §16 п.18
      (файловый архив) зафиксировать: удаление PDF счёта/КП из архива переводит документ в
      состояние «файл отсутствует» (`pdf_status=FAILED`), документ можно перерендерить; UI
      обязан показывать перерендер, а не активную кнопку скачивания. Развести коды ошибок:
      «PDF ещё рендерится» (`PENDING`) и «файл документа удалён» (новый код).
- [x] **Шаг 2 — бэк, каскад статуса.** В `apps/api/app/services/file_assets.py::delete_asset`
      перед удалением ассета найти связанные `invoices`/`quotes` по `pdf_file_asset_id` и
      выставить `pdf_status=FAILED` (+ `pdf_file_asset_id=NULL`) в той же транзакции.
- [x] **Шаг 3 — миграция-починка данных.** Новая Alembic-миграция (следующий номер после
      `0030_photo_key_indexes`):
      ```sql
      UPDATE invoices SET pdf_status='FAILED' WHERE pdf_status='READY' AND pdf_file_asset_id IS NULL;
      UPDATE quotes   SET pdf_status='FAILED' WHERE pdf_status='READY' AND pdf_file_asset_id IS NULL;
      ```
      Проверить `make alembic-check` (дриффа моделей быть не должно).
- [x] **Шаг 4 — API.** В `apps/api/app/api/v2/invoices.py:339-353` (и аналогично
      `apps/api/app/api/v2/quotes.py:743`) развести две ситуации:
      `pdf_status=PENDING` → `409 INVOICE_PDF_IN_PROGRESS` (уже есть такой класс в
      `apps/api/app/services/invoice.py:96`), `pdf_status=READY, но asset отсутствует` →
      новый код `INVOICE_PDF_MISSING` с понятным `detail` («Файл счёта удалён из архива —
      перерендерите PDF»). Аналогично для КП.
- [x] **Шаг 5 — UI.** В `apps/web/components/manager/OrderInvoicePanel.vue`:
      показывать кнопку «Перерендерить PDF» для состояния «файл отсутствует» (не только
      `FAILED`), а в тексте ошибки скачивания использовать `detail` из problem-ответа вместо
      generic «Не удалось скачать счёт» (сейчас generic — `useInvoiceDownload.ts:31-46`).
- [x] **Шаг 6 — тесты.**
      - API (`apps/api/tests/test_api_v2_invoices.py`): выдать счёт → отрендерить PDF →
        удалить файл через `DELETE /api/v1/manager/files/{id}` → в счёте `FAILED` →
        `GET .../download` → `409 INVOICE_PDF_MISSING` (не `INVOICE_PDF_NOT_READY`).
      - API: то же для КП.
      - Миграция: тест, что `READY` без asset превращается в `FAILED`.
      - UI: e2e — на странице заявки с удалённым PDF показывается «Перерендерить», а кнопка
        «Скачать» даёт внятное сообщение, а не «Не удалось скачать счёт».
- [x] **Шаг 7 — приёмка.** Свежий счёт: `POST .../invoice` → дождаться `READY` → скачать →

      перерендерить → снова `200`.

загрузке `/profile*`. По канону (`SITEMAP.md` §3) менеджер имеет все клиентские страницы, но
корзина — сущность клиента: канон и код расходятся.

**Шаги:**

- [x] **Шаг 1 — канон.** В `SITEMAP.md` §3 («Карта доступа по ролям») уточнить строку

      которые доступны только роли `CLIENT`. Заодно отметить, что `/profile*` остаются
      доступны (менеджер может смотреть свой профиль).

      Общий признак — уже существующий `auth.isClient`; при необходимости вынести в
