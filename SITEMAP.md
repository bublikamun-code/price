## 1. Стек фронтенда и роутинг

- **Фреймворк:** Nuxt 3 (Vue 3, SSR), TypeScript.
- **Роутинг:** file-based (`pages/`), reflects tree ниже.
- **Auth-middleware:** `middleware/auth.ts` — проверка JWT, редирект на `/login`.
- **Role-middleware:** `middleware/role.ts` — `meta: { roles: ['MANAGER'] }` на layout/page.
- **Адаптив:** mobile-first (640/768/1024/1280).
- **Дизайн:** см. `ARCHITECTURE_PLAN.md` §3 (плоский, воздушный, мягкие цвета, плитка).

### Layouts
- `default.vue` — публичный (шапка с лого, без sidebar).
- `client.vue` — для авторизованного клиента (sidebar + колокольчик + корзина).
- `manager.vue` — для менеджера (расширенный sidebar + dashboard-стиль).
- `auth.vue` — минимальный, только форма (без навигации).
- `miniapp.vue` — для Telegram Mini App (без шапки, mobile-only).

## 3. Карта доступа по ролям

| Роль | Доступ |
|---|---|
| **Гость** | `/`, `/login`, `/privacy`, `/brands`, `/brands/[slug]` |
| **Клиент** | все публичные + `/catalog*`, `/cart`, `/checkout`, `/orders*`, `/favorites`, `/bulk-add`, `/files`, `/profile*`, `/notifications`, `/consent` (1 раз) |
| **Менеджер** | все клиентские (как суперпользователь каталога) + `/manager/**` |
| **Mini App** | подмножество клиентских под layout `miniapp` |

> Менеджер видит каталог в режиме «без скидок» + бейджи «что видит клиент X» (preview).

## 5. Публичные страницы

### `/` — Главная
- **Роль:** public.
- **Назначение:** первый контакт, брендинг, призыв войти.
- **Блоки:**
  1. Hero-баннер (фото, заголовок, CTA «Войти в личный кабинет» → `/login`).
  2. Преимущества (3–4 плитки с иконками: «Персональные цены», «Актуальный прайс», «Быстрые заявки», «Каталоги брендов»).
  3. Краткое «Как начать работу» (3 шага: менеджер создаёт аккаунт → вы получаете доступ → заказываете).
  4. Контакты.
- **API:** нет (статика).
- **Состояния:** нет.

### `/login` — Вход
- **Роль:** public.
- **Назначение:** аутентификация по выданным менеджером логину/паролю.
- **Блоки:**
  1. Карточка-плитка по центру: поле Email, поле Пароль, чекбокс «Запомнить меня», кнопка «Войти».
  2. Ссылка «Связаться с менеджером» (Telegram-контакт).
- **Действия:** `POST /api/v1/auth/login` → при успехе редирект на `/consent` (если не принято) или `/catalog` (клиент) / `/manager` (менеджер).
- **Для менеджера после пароля:** шаг 2FA (поле TOTP-кода).
- **Состояния:** ошибка «Неверный логин или пароль», блокировка после 5 попыток (rate-limit).

### `/privacy` — Политика конфиденциальности
- **Роль:** public.
- **Назначение:** юридический текст (Закон РБ «О защите персональных данных»).
- **Блоки:** текст политики, дата редакции, реквизиты компании.
- **API:** нет.

### `/brands` — Витрина брендов (SEO, §16 п.29)
- **Роль:** public (без авторизации и consent-gate).
- **Назначение:** органический трафик по бренду; конверсия в регистрацию. Цен нет — они только в кабинете.
- **Блоки:** заголовок «Каталоги брендов», плитки брендов (название → `/brands/[slug]`), SEO-текст, CTA «Войти в кабинет».
- **API:** `GET /api/v1/public/brands`.
- **Состояния:** loading, empty («Скоро здесь появятся каталоги»), ошибка API.

### `/brands/[slug]` — Бренд: серии и номенклатура (SEO, §16 п.29)
- **Роль:** public.
- **Назначение:** посадочная под бренд/артикул из поиска.
- **Блоки:** хлебные крошки (`/` → `/brands` → бренд), название бренда, серии с thumb-фото (якоря на секции), список SKU каждой серии (name + sku), CTA-баннер «Цены доступны после входа» → `/login`.
- **API:** `GET /api/v1/public/brands/{slug}` + `GET /api/v1/public/series/{slug}/products` + `GET /api/v1/public/photo?key=` (thumb).
- **Состояния:** loading, 404 (не найден/пуст), частичная деградация без фото.
- **SEO:** `useSeoMeta` (title/description/OG); включена в `/sitemap.xml`; `robots.txt` разрешает `/brands`.

## 6. Страницы клиента

### `/dashboard` — Моя аналитика
- **Роль:** client (middleware: auth).
- **Назначение:** сводная аналитика по данным текущего клиента.
- **Блоки:**
  1. Быстрые действия: ссылка на массовое добавление, «Повторить последнюю заявку».
  2. KPI-плитки: всего заявок, заявок в этом месяце, общая сумма покупок, средний чек.
  3. График заявок за 30 дней + статусы заявок.
  4. Топ-5 товаров по количеству + последние 5 заявок.
  5. Заявки в работе (NEW/IN_PROGRESS), изменения цен в избранном, последние поступления.
- **API:** `GET /api/v1/dashboard` (агрегаты текущего пользователя, кэш Redis 60 с).

### `/consent` — Согласие на обработку ПДн (однократно)
- **Роль:** client (middleware: если `users.consent_accepted_at IS NULL`).
- **Назначение:** первый вход — клиент принимает согласие.
- **Блоки:** краткая выжимка политики, чекбокс «Принимаю», кнопка «Продолжить».
- **API:** `PATCH /api/v1/auth/me` `{consent_accepted: true}` → запись в `consent_log`.
- **После:** редирект на `/catalog`.

### `/catalog` — Каталог / Прайс-лист ⭐ (ключевая страница)
- **Роль:** client (менеджер видит то же + режим preview клиента).
- **Назначение:** просмотр товаров с персональными ценами, фильтрация, добавление в корзину.
- **Блоки:**
  1. **Панель фильтров** (левая колонка / bottom-sheet на мобиле):
     - Поиск по артикулу/наименованию.
     - Фильтр «Производитель» (мультивыбор, чипы).
     - Фильтр «Серия» (зависит от производителя).
     - Фильтр «Складской статус» (В наличии / Под заказ).
     - Кнопка «Сбросить».
  2. **Тулбар каталога:**
     - Переключатель вида: **Плитка / Таблица**.
     - Переключатель цены: **Розница / Со скидкой** (`price_mode`).
     - Переключатель расчёта: **По договору / По курсу НБ РБ** (если есть фиксация).
     - Сортировка (по имени, цене ↑/↓).
     - Кнопка «Экспорт» (CSV/XLSX/PDF с текущими фильтрами).
     - Кнопка «Выбрать все → в корзину».
  3. **Сетка карточек (плитка)** или **таблица**:
     - Карточка: фото серии (клик → lightbox+zoom), артикул, наименование, бейдж бренда, серия, статус (зелёный «В наличии» / жёлтый «Под заказ»), цена (розница зачёркнута + цена со скидкой при `discount`), поле количества, кнопка «В корзину», звёздочка избранного.
  4. **Пагинация** (page/per_page) + счётчик «Показано X из Y».
- **Действия:**
  - Добавить в корзину → `POST /api/v1/cart/items`.
  - Добавить в избранное → `POST /api/v1/favorites`.
  - Lightbox фото → модалка с zoom.
  - Экспорт → `POST /api/v1/catalog/export` → опрос `GET .../export/{job_id}` → скачивание.
- **API:** `GET /catalog/products`, `/catalog/filters`, `/catalog/export`, `/cart/items`, `/favorites`.

### `/catalog/[sku]` — Детали товара
- **Роль:** client.
- **Назначение:** подробная карточка + соседи по серии.
- **Блоки:**
  1. Хлебные крошки: Каталог / Бренд / Серия / Товар.
  2. Большое фото (lightbox+zoom), миниатюры серии.
  3. Артикул, наименование, бренд, серия, статус.
  4. **График истории цены** (фича J) — линия во времени, Δ за период.
  5. Блок цены (розница + со скидкой + display-валюта).
  6. Поле количества + «В корзину» + «В избранное».
  7. **Соседи по серии** — горизонтальный скролл карточек той же серии.
- **API:** `GET /catalog/products/{sku}`, `GET /catalog/products/{sku}/price-history`.

### `/favorites` — Избранное
- **Роль:** client.
- **Блоки:** та же сетка карточек, что в каталоге, но только избранные; кнопка «Все в корзину», «Очистить».
- **API:** `GET /favorites`, `DELETE /favorites/{productId}`.

### `/bulk-add` — Массовое добавление по SKU (фича B)
- **Роль:** client.
- **Назначение:** вставить список артикулов из Excel/текста → проверить → в корзину.
- **Блоки:**
  1. Textarea «Вставьте список»: форматы `SKU` или `SKU=qty` или `SKU\tqty` (вкладка с примерами).
  2. Кнопка «Проверить» → таблица результатов: артикул, найден?, наименование, цена, запрошенное кол-во, ошибки (не найден / нет в наличии).
  3. Чекбоксы строк + кнопка «Добавить выбранные в корзину».
- **API:** `POST /api/v1/catalog/resolve-bulk` (валидация), затем `POST /cart/items/bulk`.

### `/cart` — Корзина (черновик, фича D)
- **Роль:** client.
- **Блоки:**
  1. Таблица позиций: фото, артикул, наименование, бренд, цена за ед. (розница/скидка), количество (stepper), сумма, комментарий к позиции (фича E), удалить.
  2. Сводка справа: кол-во позиций, сумма, **кнопка «⚖️ По курсу НБ РБ»** (preview-пересчёт display-валюты), бейдж текущего курса.
  3. Поле «Комментарий к заказу».
  4. Кнопка «Оформить заявку» → `/checkout`.
  5. «Сохранить как черновик» (автосохранение каждые 30с).
- **API:** `GET/POST/PUT/DELETE /cart/items`.

### `/checkout` — Оформление заявки
- **Роль:** client.
- **Блоки:**
  1. Проверка позиций (read-only таблица с замороженными ценами).
  2. **Финальная сумма с учётом снапшота курса** (отображение: «курс зафиксирован: 3.27 BYN/USD на 2026-08-11»).
  3. Комментарий, желаемая дата отгрузки (опц.).
  4. Чекбокс «Согласен с условиями».
  5. Кнопка «Отправить заявку».
- **Действие:** `POST /api/v1/orders` → редирект `/orders/[id]` + toast «Заявка отправлена».
- **Пост-эффект:** менеджеру → Telegram + in-app; клиенту → toast + уведомление.

### `/orders` — Мои заявки
- **Роль:** client.
- **Блоки:**
  1. Фильтры: статус (Новая / В работе / Отгружена / Завершена / Отменена), период.
  2. Таблица: №, дата, кол-во позиций, сумма (с валютой), статус (цветной бейдж), кнопки «Открыть», «Повторить» (фича C), «Скачать PDF» (фича F).
- **API:** `GET /orders`.

### `/orders/[id]` — Детали заявки
- **Роль:** client.
- **Блоки:**
  1. Шапка: №, дата, статус (с историей смены статусов timeline), менеджер.
  2. Таблица позиций (snapshot цен на момент заказа, не меняется).
  3. Снапшот курса заказа.
  4. Комментарии.
  5. Кнопки: «Повторить», «Скачать PDF», «Отменить заявку» (если статус NEW).
- **API:** `GET /orders/{id}`, `POST /orders/{id}/repeat`, `POST /orders/{id}/pdf` + `GET /orders/export/{job_id}` (job-паттерн §16 п.25 вместо синхронного GET-pdf).

### `/files` — Файловый архив
- **Роль:** client.
- **Назначение:** скачивание PDF-каталогов брендов, спец-выгрузок CSV.
- **Блоки:** фильтр по типу/бренду; таблица файлов (имя, тип, размер, дата); кнопка «Скачать» (presigned URL).
- **API:** `GET /files`, `GET /files/{id}/download`.

### `/notifications` — Центр уведомлений
- **Роль:** client/manager.
- **Блоки:** список (timeline), фильтр по типу, «Отметить все прочитанными». Непрочитанные — подсветка.
- **API:** `GET /notifications`, `PATCH /notifications/{id}/read`, SSE `/notifications/stream`.

### `/profile` — Профиль
- **Роль:** client/manager.
- **Блоки (клиент):**
  1. Карточка компании: ФИО, компания, телефон, email (часть — readonly).
  2. Карточка «Мои условия»: персональная скидка по брендам (read-only таблица), зафиксированный курс (если есть).
  3. Display-валюта (селектор BYN/USD/EUR/RUB).
  4. Ссылки: Настройки уведомлений / Активные сессии.
- **API:** `GET /auth/me`, `PATCH /auth/me`.

### `/profile/notifications` — Настройки уведомлений
- **Роль:** client/manager.
- **Блоки:** таблица типов уведомлений × чекбоксы каналов (in-app / Telegram); для `PRICE_CHANGED_DIGEST` — выбор источника (корзина/избранное/заказы).
- **API:** `GET /auth/me`, `PATCH /auth/me` (настройки — поля `price_digest_*` в профиле, см. §6).

### `/profile/sessions` — Активные сессии (фича I)
- **Роль:** client/manager.
- **Блоки:** таблица сессий (устройство, IP, последний вход, текущая — бейдж), кнопка «Завершить».
- **API:** `GET /auth/sessions`, `DELETE /auth/sessions/{id}`, `DELETE /auth/sessions` (все кроме текущей; §16 п.22).

### `/profile/security` — 2FA (фича H, менеджер)
- **Роль:** manager.
- **Блоки:** QR-код для Google Authenticator, поле ввода кода подтверждения, recovery-коды (показ 1 раз), кнопка «Отключить».
- **API:** `POST /auth/2fa/setup`, `POST /auth/2fa/enable`, `POST /auth/2fa/verify` (второй шаг `/login`), `POST /auth/2fa/disable` (§16 п.22).

## 7. Страницы менеджера

> Layout `manager.vue`. Все роуты защищены `middleware/role.ts` (`roles: ['MANAGER']`).

### `/manager` — Дашборд (фича G)
- **Блоки:**
  1. KPI-плитки: заявок сегодня / за неделю, выручка за месяц, новых клиентов, активных импортов.
  2. График заявок по дням (30 дней).
  3. Топ-5 товаров по выручке.
  4. Топ-5 клиентов по выручке.
  5. Лента последних заявок (5 шт.) со статусами.
- **API:** `GET /manager/dashboard` (агрегаты, кэш Redis).

### `/manager/catalog` — Управление каталогом
- **Блоки:** таблица товаров (как каталог, но с колонками base_price, override_price, складской статус, бренд, серия, версия прайса); поиск/фильтры; ссылка на детальную карточку товара; CTA «Импортировать прайс» → `/manager/import`; кнопка «Экспорт CSV» — полная выгрузка продукции (все характеристики колонками + ссылки на фото), job-опрос → presigned URL.
- **Действия:** редактирование единичного товара (override_price вручную, статус), предпросмотр «что видит клиент X» (выбор клиента → пересчёт).
- **API:** `GET /manager/products`, `PATCH /manager/products/{id}`, `POST /manager/products/export`, `GET /manager/products/export/{job_id}`.

### `/manager/import` — Импорт прайса (CSV) ⭐
- **Блоки:**
  1. Dropzone для CSV (валидация: magic-bytes, размер ≤100МБ).
  2. Форма настроек импорта:
     - **Режим:** Upsert / Replace / Archive-missing.
     - **Валюта прайса** (BYN/USD/EUR/RUB) + **Курс** (manual / «по НБ РБ сегодня») — фича курса прайса (§17).
     - Опция «обработать ZIP с фото серий» (отдельный dropzone).
  3. Кнопка «Импортировать» → создаёт `price_list_version` (QUEUED) → Celery.
  4. **История импортов** (таблица): версия, файл, дата, статус (QUEUED/PROCESSING/DONE/FAILED), прогресс-бар, rows_ok/rows_error, действия: «Открыть отчёт» / «Откатить».
- **API:** `POST /manager/prices/import` (multipart), `GET /manager/prices/versions`.

### `/manager/import/[versionId]` — Отчёт импорта
- **Блоки:**
  1. Шапка: статус, прогресс, агрегаты (новых/обновлено/без изменений/Δ цена ↑/↓/сброшена фикс-цена).
  2. Вкладка **«Изменения цен»**: таблица SKU | старая цена | новая цена | Δ% (сортировка по Δ) — основа уведомления `PRICE_CHANGED`.
  3. Вкладка **«Ошибки»**: таблица строк с описанием ошибки; кнопка «Скачать лог ошибок» (S3).
  4. Кнопка «Откатить версию» (с подтверждением).
- **API:** `GET /manager/prices/versions/{id}`, `GET .../{id}/changes`, `GET .../{id}/errors`.

### `/manager/brands` — Бренды и серии
- **Блоки:** список брендов (плитки), внутри каждого — серии с привязанным фото; CRUD (создать/переименовать/удалить); загрузка/замена фото серии.
- **API:** `GET/POST/PATCH/DELETE /manager/brands`, `/manager/series`.

### `/manager/users` — Клиенты
- **Блоки:**
  1. Таблица клиентов: ФИО/компания, email, телефон, скидка (средняя / «—»), зафиксированный курс, статус (активен/заблокирован), дата создания, кол-во заказов.
  2. Фильтры/поиск.
  3. Кнопка «Создать клиента» → модалка (email, ФИО, компания, телефон, начальная скидка). Показ temp-пароля 1 раз.
- **API:** `GET /manager/users`, `POST /manager/users`.

### `/manager/users/[id]` — Профиль клиента + матрица скидок ⭐
- **Блоки:**
  1. Карточка клиента (редактируемые поля), статус, кнопка «Сбросить пароль».
  2. **Матрица скидок**: таблица Бренд → % скидки (inline-редактирование), кнопка «Применить ко всем брендам» (массовое), аудит-история изменений.
  3. **Курс**: блок «Зафиксировать курс» (валюта + manual / «по текущему НБ РБ» / «снять фиксацию»).
  4. **Display-валюта** клиента (BYN по умолчанию).
  5. История заказов клиента (краткая таблица).
- **API:** `GET/PATCH /manager/users/{id}`, `PUT /manager/users/{id}/discounts`, `POST /manager/users/{id}/reset-password`, `PUT /manager/users/{id}/fixed-rate`.

### `/manager/orders` — Все заявки
- **Блоки:** как `/orders` клиента, но для всех клиентов + колонка «Клиент», фильтр по клиенту/менеджеру/статусу/периоду, массовая смена статусов.
- **API:** `GET /manager/orders`, `PATCH /manager/orders/{id}` (статус).

### `/manager/orders/[id]` — Детали заявки (менеджер)
- **Блоки:** как у клиента + блок управления: смена статуса, назначение менеджера, внутренние комментарии, кнопки «Экспорт в 1С-формат (заглушка)».
- **API:** `GET /manager/orders/{id}`, `PATCH ...`.

### `/manager/files` — Загрузка файлов
- **Блоки:** список загруженных файлов (PDF-каталоги, спец-CSV); dropzone для загрузки; выбор видимости (PUBLIC/AUTHED/MANAGER_ONLY), привязка к бренду; удаление.
- **API:** `GET/POST/DELETE /manager/files`.

### `/manager/currency` — Курсы валют ⭐
- **Блоки:**
  1. Таблица последних курсов НБ РБ (USD/EUR/RUB × последние 7 дней), источник, дата.
  2. Кнопка «Обновить вручную» (форс-фетч НБ РБ).
  3. Форма «Добавить курс вручную» (валюта, значение, дата) — для override.
- **API:** `GET /manager/currencies/rates`, `POST /manager/currencies/refresh`, `POST /manager/currencies/rate`.

### `/manager/audit` — Журнал аудита
- **Блоки:** таблица действий (актёр, действие, цель, было/стало, время); фильтры по актёру/типу/периоду.
- **API:** `GET /manager/audit`.

## 8. Telegram Mini App (Этап 12, §16 п.27)

- **Layout:** `miniapp.vue` (без шапки/sidebar, mobile-only, безопасная зона Telegram).
- **Auth:** `POST /api/m/v1/auth/telegram` (по `initData` + одноразовый `link_code` при первом входе; повторные — по `initData`). Неаутентифицированному — экран связки с кодом из веб-кабинета (Профиль → Telegram), не редирект на `/login`. Данные — существующие `/api/v1/**` с Bearer.
- **Экраны (подмножество):**
  - Каталог (упрощённый, плитка, только поиск + фильтр по бренду).
  - Детали товара.
  - Корзина + оформление.
  - Мои заявки (последние 10).
  - Уведомления.
- **Ограничения:** нет массового добавления, нет дашборда, нет управления — только клиентский потребительский путь (MANAGER-линк запрещён).
- **Роль поверхности (решение по UI-аудиту, п.13):** `/m/**` — поверхность исключительно для Telegram Mini App. Мобильные браузерные пользователи работают в адаптивных клиентских страницах (`/catalog`, `/cart`, `/orders`, …); из основного интерфейса ссылки на `/m` не размещаются.

## 9. Ключевые пользовательские потоки

### Поток 1: Новый клиент делает первый заказ
```
[Менеджер создаёт аккаунт] → (показ temp-пароля)
[Клиент /login (email+temp-pass)] → /consent (принять) → /catalog
[Выбор товара, фильтры, добавить в корзину] → /cart
[Оформить заявку] → /checkout → POST /orders → /orders/[id]
[Менеджер получает TG+in-app уведомление]
```

### Поток 2: Импорт нового прайса
```
[Менеджер /manager/import]
[Загрузка CSV + ZIP фото, выбор режима/валюты/курса]
[POST /import → Celery task → прогресс в UI]
[DONE → /manager/import/[versionId] (отчёт, Δ цен, ошибки)]
[Менеджер: TG-сводка PRICE_CHANGED]
[Клиенты с затронутыми товарами в корзине/избранном: PRICE_CHANGED_DIGEST]
```

### Поток 3: Повтор заказа
```
[/orders → кнопка «Повторить» на строке]
[POST /orders/{id}/repeat → новый черновик корзины с актуальными ценами/скидками]
[Редирект /cart → проверка → /checkout]
```

### Поток 4: Фиксация курса по договору
```
[Менеджер /manager/users/[id] → блок «Курс»]
[Валюта USD, значение 3.27 (или «по текущему НБ РБ»)]
[PUT /users/{id}/fixed-rate]
[Клиент видит в шапке бейдж «курс по договору 3.27»]
[Клиент в /catalog // /cart видит цены по зафиксированному курсу]
[Кнопка «⚖️ По курсу НБ РБ» — preview пересчёта]
```

## 10. Состояния UI (universal)
