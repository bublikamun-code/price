# AGENTS.md — инструкции для ассистента (ZCode)

> Этот файл подгружается в контекст **каждой** сессии автоматически.
> Поэтому он намеренно компактный: плотные факты и правила, без воды.

## 📦 Проект (кратко)
B2B «Клиентский портал с динамическими прайс-листами». Личные кабинеты клиента/менеджера,
персональные цены, импорт CSV, заявки, уведомления, Telegram-бот.
- **Backend:** FastAPI (Python 3.12), SQLAlchemy, Alembic, Celery, Pydantic
- **Frontend:** Nuxt 3 (Vue 3 + TS + Tailwind)
- **Infra:** Docker Compose, PostgreSQL, Redis, MinIO, Nginx
- **Текущий этап:** см. `README.md` → «Дорожная карта».

## ⚡ Оптимизация расхода токенов (обязательно к исполнению)
1. **Не читай `ARCHITECTURE_PLAN.md` / `SITEMAP.md` целиком.** Читай конкретные `§N`-секции через `Grep`/`Read` со смещением. Они большие (~74KB / ~31KB).
2. **Поиск по коду/докам → делегируй агенту `Explore`.** Он вернёт вывод, а не дампы файлов в основной контекст.
3. **Изолированную реализацию (модуль, тест, эндпоинт) → делегируй `general-purpose`.** Основной контекст остаётся чистым.
4. **Параллель независимых действий** — несколько tool-call в одном сообщении.
5. **Вывод команд фильтруй**: `pytest … | tail -30`, `docker logs … --tail=50`, `| grep`. Без `cat` больших файлов.
6. **Не перечитывай файл после `Edit`** — успешный `Edit` уже гарантирует применение.
7. **Новую крупную задачу → новую сессию**, не тащи старый контекст.

## 🤖 Агенты: когда кого
| Агент | Применять для |
|---|---|
| `Explore` | «где находится…», «кто использует…», «есть ли уже…», поиск по `§N` в архитектуре |
| `general-purpose` | многошаговая реализация с чётным результатом (модель+миграция, роутер+сервис+тест) |
| напрямую (без агента) | точечная правка в 1 файле, быстрый ответ, проверка одной команды |

## 🔁 Типовые workflow по этапам
**Добавить ORM-модель (этап 1):**
`Explore` (найти §5 + существующие модели как референс) → `general-purpose` (модель в `models/`, схема в `schemas/`, миграция `make migrate-gen m="…"`).

**Добавить эндпоинт API:**
`Explore` (§6 контракт + похожий роутер) → `general-purpose` (тонкий роутер `api/v1/` + use-case в `services/` + репозиторий в `repositories/` + тест).

**Добавить экран Nuxt:**
`Explore` (секция в `SITEMAP.md` + существующая страница как референс) → `general-purpose` (`pages/`, при необходимости `layouts/`/`middleware/`) → `web-gui-tester` проверить визуально.

**Проверить фронт после правок:**
`make up` → `web-gui-tester` (клик/скриншот), без ручного описания DOM.

## 📐 Принципы проекта (без цитирования — см. § в архитектуре)
- **Сначала документ — потом код** (`ARCHITECTURE_PLAN.md` §21): отклонение от канона → сначала правка док-та, потом код.
- **Чистая архитектура:** `api → services → repositories → models` (§4). Роутеры тонкие.
- **API-first:** контракт эндпоинта описан в §6; реализация ему соответствует.
- **Безопасность:** JWT, RBAC, rate-limit, валидация загрузок (§11).
- **Коммиты/правки:** только когда явно попросили. Если правишь канон — поднимай вопрос, не молча меняй.
