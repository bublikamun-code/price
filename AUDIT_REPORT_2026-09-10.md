## 🐞 Найденные и исправленные баги

### БАГ #1 (P0) — SSR-запросы уходили без Authorization → случайные разлогины
`apps/web/plugins/api.ts`. `useCookie()` внутри `onRequest` перехватчика `$fetch`
терял Nuxt-контекст при вложенных вызовах после `await` (страница бренда:
бренд → серии → товары). SSR получал 401, клиент считал сессию мёртвой,
дергал refresh → logout и чистил httpOnly-куки. **Фикс:** `nuxtApp.runWithContext()`.
Побочный эффект: страница `/brands/keaz` показывала «Номенклатура уточняется»
вместо 61 товара (SSR-ошибка глоталась try/catch). Проверено: SSR теперь отдаёт все позиции.

### БАГ #2 (P1) — кнопка «Скачать PDF» заявки: 500
Задача `app/tasks/export_order_pdf.py` была заглушкой и не совпадала по имени
(`run_export_order_pdf` vs `run_order_pdf`) → ImportError на каждый запрос.
**Фикс:** реализована полная Celery-задача (RUNNING → заказ/позиции/клиент →
шаблон `app/templates/pdf/order.j2` (новый) → weasyprint → S3 → DONE) + поллинг
отдаёт presigned URL. Проверено end-to-end: job DONE, файл в `csv-exports`.

### БАГ #3 (P1) — кнопка «Excel» заявки: 500
`DELIVERY_METHOD_RU` импортировалась из `services/email.py`, но нигде не была
определена (упало бы при первом же обращении). **Фикс:** словарь добавлен.
Проверено: `GET /orders/{id}/export.xlsx` → 200, 5.3 KB.

### БАГ #4 (P2) — сохранение матрицы скидок сломано
`manager/users/[id].vue`: `v-model` на `type="number"` держит **число**, а код
вызывал `.trim()` → `TypeError: n.trim is not a function`, PUT не отправлялся,
менеджер не мог сохранить скидки. Тот же класс бага: курс фиксации (`fixRate`,
`validRate`) и редактирование цены/остатка товара (`manager/catalog.vue` —
менеджер не мог сохранить цену/остаток). **Фикс:** `String(...)` приведения +
устойчивые валидаторы. Проверено: скидка сохраняется в БД.

### БАГ #5 (P2) — потеря имени клиента в списке заявок менеджера
После «В сборку» строка заменялась ответом PATCH, который не обогащался
`client_name` → в списке появлялся `№adeaa687`. **Фикс:** PATCH
`/manager/orders/{id}` теперь возвращает `clients=` как GET.

### БАГ #6 (P2) — несогласованность витрины бренда
`GET /public/brands/keaz` отдавал `series_count: 0, products_count: 0, photo: null`
при живых данных (список брендов отдавал корректные). **Фикс:** `get_brand`
считает статистику через `fetch_brand_stats`.
